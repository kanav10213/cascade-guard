Cascade Guard

checking server…

In a chain of AI agents, one agent's mistake gets accepted by the next and builds up until it reaches the final answer. Cascade Guard checks every step, re-runs a failing step, and stops the order if it can't be fixed, so a wrong answer is never delivered silently.

New: Ask Cascade Guard, an assistant you talk to in plain English (check a bill, a sum or an agent chain's answer). Also: build your own agent chain (section 9) and connect the agents you already have (section 10).

3. Pilot: invoice checking

A real-world workflow on LangGraph: read the invoice, price it, approve it, write the summary. Every step is checked before the next one uses it. Paste your own invoice in the same layout, or use a sample.

Injected errors imitate real ones: a price with the decimal point moved, a wrong quantity, a dropped or duplicated line, a wrong tax rate, a flipped approval. Some mistakes are systematic and come back on a blind retry; with guided repair the agent is told exactly what was wrong (simulated for the rule agents, real for LLM agents).

8. Evaluate a model: measured error rates

  
The full evaluation, the same as cascade-guard eval: how often each agent is right, how many errors the checker catches and how often it wrongly rejects, and what the guard does end to end. Every rate comes with a 95% interval. Each seed is one independent repeat; results are pooled. Results are also saved in results/.

  

    
    
    
    
    
    
    
  

  

  

  

  

  





  
9. Build your own agent chain

  
Design your own multi-step agent, or plug in agents you already have: each step is done by the model or by your own agent at a URL. Give each step an instruction, choose what it returns and how it is checked. Every step works on the previous step's output, is checked before the next step uses it, is retried with the reason when it is wrong, and stops the chain safely if it stays wrong. Nothing here is fixed: chains are saved in the database and run on LangGraph, built from your definition.

10. Connected agents

  
Connect an agent you already have (any language, any framework) once, test it, and then choose it by name in any chain step ("Done by"). Cascade Guard sends it the step's instruction and input, checks its answer, retries it with the reason, and stops the chain if it stays wrong. The agent must answer {"output": ...}; see INTEGRATION.md or examples/my_agent_server.py. A token is never stored here: give the name of a server setting that holds it.
